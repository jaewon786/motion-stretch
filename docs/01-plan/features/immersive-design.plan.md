# immersive-design 계획서 (디자인 리뉴얼)

- 작성일: 2026-11-24 · 작성 도구: bkit pdca(plan) + ECC frontend-design-direction + LeanREA
- 기준 문서: `PRD.md`(무엇을·왜) — 이번 작업은 **새 기능 없이 화면 표현만 바꾼다** (PRD 6번 범위 유지)
- 요청: "igloo.inc의 3차원 인터랙티브 느낌을 스포츠테크 주제로 우리 사이트에 넣기"

## 목표
첫 화면을 "스크롤하면 카메라가 움직이는 영화 같은 3D 모션 랩(Pose Lab)"으로 바꿔, 이 앱이 **몸을 관절 점으로 읽고 정답 각도와 비교하는 기술**이라는 것을 글보다 먼저 보여 준다. 나머지 화면은 같은 디자인 언어(HUD·단색 톤)로 맞춘다.

## 참고 사이트 분석 (LeanREA, 증거 구분)

| 가져오지 않는 것 | 브랜드·모델·텍스처·코드. 기법과 분위기만 참고해 새로 만든다 |

## 성공 기준
| 번호 | 기준 | 확인 방법 |
|---|---|---|
| DS-1 | 첫 화면 3D가 스크롤에 따라 3막(스캔 → 비교 → 종목 선택)으로 카메라가 이동한다 | 첫 화면을 끝까지 스크롤하며 확인 |
| DS-2 | 마우스를 움직이면 3D 장면이 살짝 따라 기울어진다(시차) | 마우스 이동 |
| DS-3 | 종목 카드에 마우스를 올리면 3D의 같은 종목 코어가 빛난다 (HTML ↔ 3D 연동) | 카드 위에 마우스 |
| DS-4 | 기존 기능과 성공 기준 유지: 종목 카드 클릭 1번째(SC-5), 카메라 모드 인식 속도 20회/초 이상(SC-2) | 클릭 수, 인식 속도 표시 |
| DS-5 | 움직임 줄이기 설정이면 카메라 이동·입자 애니메이션을 멈춘다. 글자 대비·키보드 초점 유지 | OS 설정, 키보드 Tab |
| DS-6 | 넓은 화면(1440×900)과 좁은 화면(390×844)에서 글자가 겹치거나 넘치지 않는다 | 두 크기에서 화면 확인 |
| DoD | `npm run lint`·`npm run build` 통과, 기존 화면(동작 목록·스트레칭 화면) 동작 그대로 | 명령·화면 확인 |

## 작업 목록
1. 디자인 토큰 바꾸기: 차가운 실험실 톤 팔레트, 고정폭 글꼴(Geist Mono, 로컬 파일), 그레인·HUD 공통 스타일
2. 첫 화면 3D 장면: 입자로 된 스캔 선수(자세가 바뀌며 흩어졌다 모임), 스캐너 고리·스캔 빛, 실험실 바닥 격자, 떠다니는 먼지, 후처리(빛 번짐·그레인·비네트)
3. 스크롤 카메라 연출(3막) + 마우스 시차 + 움직임 줄이기 대응
4. 2막 HUD: 관절 표식·각도 호·고정폭 각도 라벨(실제 각도 계산 함수 사용)
5. 3막: 종목 코어 4개 + 종목 카드 마우스 연동
6. 첫 화면 구성 다시 짜기(부팅 인트로, 3막 글, HUD 카드), 동작 목록·스트레칭 화면에 같은 디자인 언어 적용
7. 넓은·좁은 화면 확인, 성능 확인, lint·build

## 위험과 대응
| 위험 | 대응 |
|---|---|
| 첫 화면 3D가 무거워 느린 기기에서 끊김 | 캔버스 1개만 쓰고, 성능이 떨어지면 후처리·입자 수를 자동으로 줄임(PerformanceMonitor), 해상도 상한 |
| 화려한 연출이 기능을 가림 | 종목 카드·버튼은 HTML 그대로(클릭 수·접근성 유지), 3D는 뒤 배경(aria-hidden) |
| 카메라 모드 인식 속도 저하 | 스트레칭 화면의 3D 설정(효과 끔)은 바꾸지 않음 |
| 가상 스크롤로 키보드·화면 낭독기 사용이 어려워짐 | 진짜 스크롤을 그대로 쓰고 카메라만 스크롤 위치를 부드럽게 따라가게 함 |
