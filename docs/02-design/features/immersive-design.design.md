# immersive-design 설계서 (디자인 리뉴얼)

- 기준: `docs/01-plan/features/immersive-design.plan.md`, `PRD.md`, `DESIGN.md`(기능 설계는 그대로)

## 0. 디자인 방향 (ECC frontend-design-direction 계약)
| 항목 | 결정 |
|---|---|
| 목적 | 운동 전에 종목을 고르고 자세 교정을 시작하게 하는 것. 첫 화면은 "이 앱이 몸을 어떻게 읽는지"를 보여 준다 |
| 사용자 | 운동 전 PC 앞의 생활체육인. 첫 방문에는 신뢰·흥미, 재방문에는 빠른 종목 선택 |
| 톤 | 기술적·영화적·절제된 "모션 캡처 실험실". 단색 회청색 바탕 + 라임(내 동작·행동 버튼)·하늘색(정답) 두 강조색 |
| 기억에 남을 한 가지 | 스크롤하면 입자로 된 선수가 관절 점·뼈대로 분해되고, 각도 호와 고정폭 숫자가 붙는 "스캔 장면" |
| 제약 | Next.js 16 고정, 새 의존성은 글꼴(geist) 하나, 진짜 스크롤 유지, 움직임 줄이기 존중, 카메라 모드 성능 유지 |

## 1. 화면 구성 — 첫 화면 `/`
```
[고정 배경] 전체 화면 3D 캔버스 (aria-hidden, 내용 뒤)
[부팅 인트로] 00→100% 보정 숫자 + "CALIBRATING SENSORS" (1.4초, 세션당 1번, 움직임 줄이기면 생략)
[1막 HERO 100vh]   왼쪽: HUD 라벨 · 큰 제목 · 한 줄 소개 · [종목 고르기] · [작동 원리 보기]
                   오른쪽 아래: HUD 판독값(SCAN / JOINTS 33 / ±15° TOL)
[2막 SCAN 100vh]   오른쪽 글: "01 / SCAN — 몸을 관절 33개로 읽어요" (카메라가 다가가고 입자가 뼈대로 분해)
[3막 COMPARE 100vh] 왼쪽 글: "02 / COMPARE — 정답 각도와 ±15°" (각도 호·숫자 라벨)
[4막 CHOOSE]       "03 / CHOOSE" 종목 HUD 카드 4개 (뒤에서 종목 코어 4개가 돌고, 카드에 올리면 해당 코어가 빛남)
[진행 방법·안전 고지·바닥글]
```

## 2. 3D 장면 구성 (`components/experience/`)
| 요소 | 방법 |
|---|---|
| 입자 선수 | 포즈 엔진(`solvePose`) 관절 점에서 팔다리 원기둥·몸통 타원 표면을 고르게 뽑은 점 약 7천 개. 자세 바꿈은 관절 점 보간 → 매 프레임 점 위치 다시 계산. 가산 혼합 점 셰이더(높이별 색, 스캔 띠 밝게, 반짝임) |
| 분해 효과 | 스크롤 2막에서 점이 바깥으로 흩어지고 뼈대 선·관절 표식이 나타남 (셰이더 uniform) |
| 스캐너 | 위아래로 훑는 고리 2개 + 수평 스캔 띠(점 셰이더와 같은 높이 값 공유) |
| 바닥 | 셰이더 격자(가운데에서 멀어질수록 사라짐) + 동심원 |
| 먼지 | 천천히 떠다니는 점 1,200개 |
| 각도 HUD | 무릎·엉덩이 각도 호(선) + HTML 라벨(고정폭 숫자, `computeAngles`로 실제 계산) |
| 종목 코어 | 와이어프레임 결정 4개(축구=깎은 정이십면체, 러닝=고리, 농구=구 이음선, 테니스=정십이면체)가 선수 주위를 돎. 카드 마우스 → 해당 코어 확대·발광 |
| 후처리 | 빛 번짐, 필름 그레인, 비네트, 아주 약한 색수차. 성능 저하 시 끔 |
| 카메라 | 스크롤 진행도(0~1) 키프레임 사이를 보간 + 마우스 시차, 감쇠로 부드럽게 |

## 3. 데이터 흐름
```
window 스크롤 → scrollProgress(0~1) ─┐
마우스 위치 → pointer(-1~1) ──────────┼→ 카메라 리그(useFrame, 감쇠) → 장면
종목 카드 hover → hoveredSport 저장소 ┘           └→ 막별 값(분해 정도·HUD 투명도·코어 강조)
```
- 저장소는 새 라이브러리 없이 작은 모듈(`lib/experience/store.ts`)로 만든다. 매 프레임 값은 React 다시 그리기 없이 읽는다.

## 5. 상태 (ECC 콘텐츠 상태 계약)
| 상태 | 처리 |
|---|---|
| 로딩 | 부팅 인트로 + 3D 준비 전 정적 그라데이션 배경 (글·카드는 바로 사용 가능) |
| 빈 상태 | 해당 없음 — 종목 데이터는 코드에 고정 4개 |
| 오류 | WebGL이 없으면 3D를 그리지 않고 정적 배경만 (글·카드 그대로) |
| 부분 | 성능 저하 시 후처리 끔, 핵심 장면 유지 |
| 성공 | 카드 클릭 → 동작 목록 이동 (기존과 같음) |
| 권한 | 첫 화면은 카메라를 쓰지 않음 — 해당 없음 (카메라 권한은 스트레칭 화면 기존 처리) |
